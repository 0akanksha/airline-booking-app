# Aerion — Airline Booking App

Full-stack flight search & booking demo: React + Vite + Tailwind frontend, Express backend, live flight search/booking via the Duffel API (test mode), admin dashboard — all served from a single process/port.

## Stack

- **Frontend**: React + Vite, Tailwind CSS v4, React Router
- **Backend**: Express (in `server/`), same process/port as the frontend
- **Flights & bookings**: Duffel API — real airline fares, seat maps, and baggage ancillaries, booked against Duffel's test-mode simulated balance (no Stripe/real payment involved)
- **Database**: Neon serverless Postgres via Drizzle ORM — admin auth only (`users` table); flights and bookings are not stored locally, Duffel is the system of record
- **Auth**: JWT httpOnly cookie, bcrypt — admin-only accounts (passenger booking is guest, no signup)
- **Live flight status**: aviationstack (independent of booking data — works for any real-world flight number)

## Local development

```bash
npm install
npm install --prefix server
cp server/.env.example server/.env   # fill in DATABASE_URL, JWT_SECRET, ADMIN_EMAIL/PASSWORD, AVIATIONSTACK_API_KEY, DUFFEL_API_KEY
npm run db:push --prefix server      # push schema to Neon (users table only)
npm run dev                          # http://localhost:4000 by default
```

`DUFFEL_API_KEY` is a `duffel_test_...` token from the Duffel dashboard — required for search, booking, seat maps, and the admin bookings list.

## Admin

No public signup — the admin account is seeded from `ADMIN_EMAIL`/`ADMIN_PASSWORD` in `server/.env` on first server start. Sign in at `/admin/login`. The dashboard lists real bookings pulled live from Duffel (`GET /air/orders`), not a local table.

## Known limitation

Booking cancellation isn't implemented yet — Duffel's order cancellation is a separate quote-then-confirm flow. `/manage` is currently view-only.

## Deploy (Render)

Single Web Service, defined in `render.yaml`:

- **Build**: `npm run build:all`
- **Start**: `npm start`
- **Health check**: `/api/health`

Required env vars (set in the Render dashboard, not committed):

| Var | Notes |
|---|---|
| `DATABASE_URL` | Neon pooled connection string |
| `JWT_SECRET` | auto-generated by Render |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | seeds the initial admin user |
| `AVIATIONSTACK_API_KEY` | live flight status lookup |
| `DUFFEL_API_KEY` | flight search, booking, seat maps — use a `duffel_test_...` token |

`NODE_ENV` is intentionally **not** set as a platform env var — it's set to `production` only inside `server/package.json`'s `start` script. Setting it at the platform level makes `npm install` skip devDependencies during the build step, which breaks `vite build`/`tsc`.
